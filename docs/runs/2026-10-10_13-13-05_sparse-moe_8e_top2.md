The MoE run achieved 9.74% lower best LM validation loss, at the cost of 1.82× training time,
1.99× peak allocated VRAM, and 5.50× total parameters. It still activates only two experts per
token per block call. All experts received assignments at every logged checkpoint; final
assignment shares ranged from 9.6% to 15.0%, with router auxiliary loss 1.0147. These sampled
diagnostics show balanced routing without expert collapse at the recorded checkpoints.

The model completed all 10,000 steps, sampled the same 81.92 million training bytes as the baseline,
validated 20 times, saved best/final checkpoints, reloaded the best checkpoint, and generated 200 bytes.
Both checkpoints' configurations and parameter counts were verified after training; final weights are finite.

Sparse dispatch remains the implementation tested before this run: only selected token rows enter each expert.
The pre-run full-configuration smoke test observed 98,304 expert-token rows across six block calls, compared
with 393,216 for evaluating all eight experts on every token. Two full-size experts per token increase
feed-forward work relative to one dense SwiGLU, and the explicit Python dispatch loop adds gather/scatter
and synchronization overhead. Sparse execution saves work relative to evaluating all experts, while all
expert weights and optimizer states still occupy VRAM.

This is a single seeded run with randomly sampled validation batches, and the dense result is historical.
The surrounding architecture, dataset splits, batch size, context, training budget, and timing definition match; random
initialization and subsequent sample sequences differ because the larger model consumes more RNG draws.
There is no repeated-seed variance estimate or fixed validation sweep, so small differences in validation
loss should be interpreted with those limits. Best checkpoint selection uses LM loss only.

At step 10,000, training LM loss was **0.6186**, router auxiliary loss **1.0147**,
and validation LM loss **0.5758**. Uniform routing has auxiliary loss 1. Final logged expert
utilization is the fraction of assignments from the last training batch, summed over both recurrent passes
for each unique block; percentages are rounded and are not run-wide utilization statistics.
