## Observations

The smoke script (`artifacts/bpe-smoke/smoke.py`) reads the existing cached Arrow
files directly, selecting the standard split percentages. It trains and encodes
the complete intended tokenizer corpus, while only the model training is reduced
to two small steps. The default model parameter counts were independently checked
by constructing both vocabularies on PyTorch's meta device. All architecture
and optimizer defaults for the real experiment remain unchanged.

Token byte lengths are computed once from the reversible ByteLevel vocabulary
and looked up by shifted validation target ID. Their sums reproduce source UTF-8
byte totals exactly, including partial Unicode characters and newline merges.
Checkpoint reconstruction preserved token IDs and generation produced 32 decoded
UTF-8 bytes with six BPE tokens for a 30-byte budget. The full tokenizer JSON and
metadata are embedded in the checkpoint; the local standalone JSON is a smoke
artifact, not a generation dependency.

BPE covers more source bytes at the same token context and training step budget,
and expands vocabulary parameters/softmax work. Compare BPB rather than token
loss. Sampled validation is uniform over tokens, so byte/BPE windows differ and
this is not full-corpus compression with fixed byte contexts. Preparation time
is outside training-step throughput. Invalid generated UTF-8 is counted after
replacement, unlike the historical raw-byte generation count.

In the preserved script output, `tokenizer_seconds` is the entire preparation and
smoke workflow duration, despite its name; tokenizer training itself took 31.23s.
The script was subsequently corrected to distinguish those timers.
