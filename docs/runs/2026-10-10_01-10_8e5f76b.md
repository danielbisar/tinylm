## Model and training

Vocabulary: 256 byte values, with a learned byte embedding and an untied linear next-byte output head. PyTorch MultiheadAttention with causal mask and biased projections.

Each unique block applies pre-normalization, causal attention with a residual connection, then pre-normalization and the feed-forward network with another residual connection. The sequence of 3 unique blocks is traversed 2 time(s), sharing weights between passes. A final LayerNorm precedes the output head.

TinyStories: `train[:5%]` for training; `validation[:1%]` for validation. Stories joined with newlines and encoded as UTF-8 bytes.

Training uses random contiguous chunks, next-byte cross-entropy, and AdamW with learning rate `3e-4` (other optimizer settings use PyTorch defaults). The random seed is 42. Every 500 steps, averaged over 20 random batches; best checkpoint selected by validation loss.

Generation uses greedy argmax over the last context window, decoding UTF-8 with replacement for invalid byte sequences. Best and final checkpoints are saved as `best_model.pt` and `last_model.pt`; generation reloads the best checkpoint.

### %5 trainig set

Interesting: using 5% training data produced almost the same validation loss as 1%.
1% data: best val ≈ 0.7820
5% data: best val ≈ 0.7826

So at this training budget, data diversity is not the bottleneck. The model itself/training setup is now the stronger candidate.
